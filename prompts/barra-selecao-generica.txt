ETAPA B — COMPONENTE GENÉRICO (shared, na pasta do app-menu-acoes)
========================================================================
Nome sugerido: app-barra-selecao (standalone). Se o projeto já usar outro padrão de nome em shared, siga o padrão.

API:
- @Input() quantidade: number                                  // nº de itens selecionados
- @Input() rotuloSingular = 'selecionado'; @Input() rotuloPlural = 'selecionados'   // Tarefas passa 'selecionada'/'selecionadas'
- @Input() acoes: AcaoBarraSelecao[]
- @Input() modo: 'icone' | 'icone-texto' = 'icone-texto'      // Tarefas usa 'icone' (como hoje); Documentos usa 'icone-texto'
- @Input() mostrarLimpar = true
- @Output() acao = new EventEmitter<string>()                  // emite o id da ação
- @Output() limpar = new EventEmitter<void>()

interface AcaoBarraSelecao {
  id: string;
  rotulo: string;              // texto (modo icone-texto) e tooltip/aria-label (modo icone)
  icone: string;               // nome do e-icon
  variante?: 'padrao' | 'sucesso' | 'perigo';
  desabilitado?: boolean;
  motivoDesabilitado?: string; // tooltip quando desabilitado
}

Regras:
- O componente é SÓ exibição: não conhece Tarefas nem Documentos e não chama serviço. Quem usa decide as ações e trata o (acao).
- Aparece só quando quantidade > 0 (o @if fica no componente ou no pai, siga o que Tarefas faz hoje).
- Só desktop e tablet: no celular não renderiza (mesma regra de breakpoint de A4, centralizada no componente).
- role="toolbar", aria-label "Ações em lote"; cada botão com aria-label; ação desabilitada com disabled e tooltip do motivo.
- Entrada com a animação suave do mock (fade/slide de baixo, 200ms). Respeitar prefers-reduced-motion.
