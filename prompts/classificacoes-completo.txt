1. CONTRATO DE DADOS — UMA COLEÇÃO SÓ (o Jeziel cria no banco; você só lê/grava conforme isto)
========================================================================
Estrutura em ÁRVORE de 3 níveis, numa única coleção (nome sugerido: `classificacoes`; ajuste ao padrão do projeto e informe):
  Nível 1 — GRUPO (ex.: "Petição inicial", "Petição intermediária", "Recursos" — veja o JSON do Gerador de Peças, A1)
    Nível 2 — CATEGORIA (ex.: "Direito Civil", "Direito do Trabalho"…)
      Nível 3 — SUBCATEGORIA / PEÇA (ex.: "Ação de Cobrança") ← é a que se aplica ao arquivo
Documento da coleção:
{ _id, nivel: "grupo" | "categoria" | "subcategoria", paiId (null no grupo), tenantId (null = PADRÃO do sistema), nome, cor (hex; usado no grupo/categoria, a subcategoria herda da categoria), icone, ordem,
  palavrasChave: [string] (subcategoria; palavras padrão),
  palavrasEscritorio: [{ tenantId, palavra, origem: "manual" | "aprendizado", criadoPor, criadoEm }] (palavras extras/aprendidas por escritório, inclusive em itens padrão),
  ocultoPara: [tenantId] (escritórios que ocultaram um item PADRÃO),
  padrao: bool, ativo: bool, criadoPor, criadoEm, atualizadoPor, atualizadoEm }
No DOCUMENTO (arquivo da Nova Cloud): classificacao: { subcategoriaId, categoriaId, grupoId, classificadoPor, classificadoEm } (ausente/null = "sem classificação"; arquivos antigos continuam funcionando).
Índices (o Jeziel cria; entregue os comandos):
- classificacoes: { tenantId: 1, nivel: 1, ativo: 1, ordem: 1 }; { paiId: 1, ativo: 1 }; { "palavrasEscritorio.tenantId": 1 }
- documentos: { tenantId: 1, "classificacao.subcategoriaId": 1 }; { tenantId: 1, "classificacao.categoriaId": 1 }; { tenantId: 1, "classificacao.grupoId": 1 }
Arquivo de carga (ENTREGAR, NÃO EXECUTAR): `classificacoes-padrao.json` gerado do JSON do Gerador de Peças (A1), respeitando a hierarquia dele (grupos → categorias → subcategorias), com tenantId null, padrao true, ordem, cor da paleta de gráficos do UI-Kit por categoria, ícone por categoria e palavrasChave iniciais extraídas do nome da subcategoria (minúsculas, sem acento, sem stopwords: de, da, do, ação, para, com, em…; palavras com 4+ letras). Inclua um grupo "Documentos de apoio" (Procuração; Documento pessoal (RG, CPF, comprovante de residência); Contrato; Comprovante financeiro (recibo, nota fiscal); Prova / Print de conversa; Ata de audiência; Sentença / Decisão; Planilha / Cálculo) com palavras-chave específicas (procuracao, outorga, poderes, ad judicia, substabelecimento / rg, cpf, identidade, cnh, residencia …). Entregue os comandos mongoimport/mongosh (coleção + índices) como texto.
Regras de escopo:
- O escritório vê: itens padrão ativos que NÃO estão em ocultoPara + itens do próprio tenant.
- O que qualquer usuário do escritório (titular ou adicional) cadastra fica com tenantId do escritório e aparece para TODOS do escritório.
- Itens PADRÃO: não podem ter nome editado nem ser excluídos; podem ser OCULTADOS/mostrados pelo escritório (ocultoPara) e receber palavras extras do escritório (palavrasEscritorio). O escritório pode criar categorias próprias dentro de um grupo padrão e subcategorias próprias dentro de uma categoria padrão.
- Itens PRÓPRIOS: CRUD completo (grupo, categoria, subcategoria). Nome único (sem acento/maiúsculas) entre irmãos visíveis.
- Excluir item próprio com arquivos classificados (ele ou descendentes): confirmação com a contagem; ao confirmar, limpar a classificação desses arquivos ($unset) e excluir o item e os descendentes. Excluir grupo/categoria apaga em cascata os filhos próprios.

2. BACK-END (Controller → Business → Repository, no CloudController, padrão de develop)
========================================================================
Rotas (prefixo e nomes no padrão do CloudController; erros com objeto de resultado + errorId):
- GET    classificacoes → árvore visível ao escritório: { grupos: [{ id, nome, cor, icone, padrao, oculto, totalArquivos, categorias: [{ id, nome, cor, icone, padrao, oculto, totalArquivos, subcategorias: [{ id, nome, palavrasChave (padrão + escritório), padrao, oculto, totalArquivos }] }] }], totais: { grupos, categorias, subcategorias, classificados, semClassificacao } }
- POST   classificacoes              { nivel, paiId, nome, cor?, icone?, filhos?: [nome] }  (filhos: para cadastrar categoria já com subcategorias separadas por ";")
- PUT    classificacoes/{id}         { nome, cor?, icone?, palavrasChave? }  (próprios: tudo; padrão: só palavrasChave extras → palavrasEscritorio origem "manual")
- PUT    classificacoes/{id}/ocultar { oculto: bool }                         (só padrão)
- DELETE classificacoes/{id}                                                   (só próprios; cascata + limpeza dos arquivos)
- GET    classificacoes/historico?pagina&tamanhoPagina → log geral (ver abaixo)
- PUT    documentos/classificacao    { documentoIds: [], subcategoriaId | null }   (lote; null remove)
- GET    documentos/sem-classificacao?pagina&tamanhoPagina → { itens: [documento resumido + sugestoes top 3], total, sugestoesConfiaveis }
- GET    documentos/{id}/sugestoes-classificacao → [{ subcategoriaId, nome, categoriaNome, grupoNome, cor, confianca, motivos[] }]
- POST   documentos/classificacao/aplicar-sugestoes { minimoConfianca: 80 }
- Listagem de documentos (lista/grade/"Carregar mais"): incluir classificacao { subcategoriaId, subcategoriaNome, categoriaNome, grupoNome, cor } no DTO e aceitar o filtro { grupoIds[], categoriaIds[], subcategoriaIds[], semClassificacao } (Classificação deixa de ser "Em breve").
LOG GERAL DE CLASSIFICAÇÕES (obrigatório):
- Toda ação de gestão gera log na estrutura de logs de develop (A3), com módulo/categoria "Classificações": usuário (nome; titular ou adicional), ação (cadastrou, editou, renomeou, alterou cor, excluiu, ocultou, mostrou, adicionou palavras-chave), alvo (nível + nome, com o caminho "Grupo › Categoria › Subcategoria"), antes → depois quando for edição, data/hora, tenant.
- Aplicar/alterar/remover a classificação de um ARQUIVO também gera log (no log do documento E no geral de Classificações): "classificou X como <subcategoria>", "alterou de A para B", "removeu a classificação de X". Aplicação em lote: um log por arquivo + um resumo ("aplicou 12 sugestões").
- GET classificacoes/historico devolve esse log do escritório, paginado (padrão de paginação de Clientes), mais recente primeiro.
SUGESTÃO INTELIGENTE (no BACK; o front só exibe) — sobre as SUBCATEGORIAS visíveis:
- Normalizar (minúsculas, sem acento, só [a-z0-9 ]). "frase" = nome sem parênteses e sem "ação de/da/do" no início.
- Pontuação: frase no NOME do arquivo +55; senão frase no TEXTO extraído (se houver) +32; palavras-chave (padrão + escritório) com peso IDF (log((total+1)/df)+0,4): no nome min(45, Σidf×14), no texto min(28, Σidf×6); palavra no caminho da PASTA +10; extensão (xlsx → "Planilha / Cálculo" +30; imagem → "Prova / Print de conversa" +30); ≥ 50% dos arquivos classificados da mesma pasta usam a subcategoria → + round(20 × proporção).
- confiança = min(98, pontuação); descartar < 35; top 3 com motivos em texto ("nome contém “cobranca”", "pasta “Cobrança”", "70% dos arquivos da pasta são deste tipo").
- IDF por escritório em cache (IMemoryCache), invalidado ao alterar itens/palavras.
- Nunca aplicar sozinha.
APRENDIZADO: classificar com subcategoria DIFERENTE da sugestão principal → a palavra mais característica do nome do arquivo (maior IDF, 4+ letras, não stopword, ainda não é palavra-chave) entra em palavrasEscritorio (origem "aprendizado") daquela subcategoria, para o escritório. Retornar { aprendido: "palavra" } e registrar no log geral.
Performance: paginação em tudo que lista; sugestões só para a página atual; árvore carregada uma vez por request; sem N+1.
