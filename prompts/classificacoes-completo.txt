2. BACK-END (Controller → Business → Repository, no CloudController, padrão de develop)
========================================================================
Rotas (prefixo e nomes no padrão do CloudController; erros com objeto de resultado + errorId):
- GET  classificacoes                     → { areas: [{ id, nome, cor, icone, padrao, apoio, oculta, totalArquivos, pecas: [{ id, nome, palavrasChave, padrao, oculta, totalArquivos }] }], totais: { areas, pecas, classificados, semClassificacao } }
- POST classificacoes/areas               { nome, cor, icone?, pecas?: [nome] }  (pecas separadas por ";" no front)
- PUT  classificacoes/areas/{id}          { nome, cor }            (só próprias)
- DELETE classificacoes/areas/{id}        (só próprias; ver regra de exclusão)
- PUT  classificacoes/areas/{id}/ocultar  { oculta: bool }         (padrão)
- POST classificacoes/areas/{areaId}/pecas { nome, palavrasChave? }
- PUT  classificacoes/pecas/{id}          { nome, palavrasChave }  (só próprias; nas padrão só palavrasChave extras do escritório → gravar em classificacoes_aprendizado com origem "manual")
- DELETE classificacoes/pecas/{id}        (só próprias)
- PUT  classificacoes/pecas/{id}/ocultar  { oculta }
- PUT  documentos/classificacao           { documentoIds: [], pecaId | null }   (lote; null = remover; registra log por documento)
- GET  documentos/sem-classificacao?pagina&tamanhoPagina → { itens: [{ documento resumido + sugestoes top 3 }], total, sugestoesConfiaveis (≥ 80%) }
- GET  documentos/{id}/sugestoes-classificacao → [{ pecaId, nome, areaNome, cor, confianca (0–98), motivos: [string] }]
- POST documentos/classificacao/aplicar-sugestoes { minimoConfianca: 80 } → aplica a sugestão principal em todos os pendentes com confiança ≥ mínimo; retorna quantos.
- Listagem de documentos (lista/grade/"Carregar mais"): incluir classificacao { pecaId, pecaNome, areaNome, cor } no DTO e aceitar filtro classificacao: { areaIds[], pecaIds[], semClassificacao: bool } (Classificação deixa de ser "Em breve").
SUGESTÃO INTELIGENTE (no BACK; o front só exibe). Port do algoritmo do mock, por documento:
- Normalizar (minúsculas, sem acento, só [a-z0-9 ]).
- "frase" da peça = nome sem parênteses e sem "ação de/da/do" no início.
- Pontuação: frase contida no NOME do arquivo +55; senão frase no TEXTO extraído (se o documento tiver texto) +32; palavras-chave da peça (padrão + aprendidas do escritório) com peso IDF (log((totalPeças+1)/df)+0,4): no nome soma min(45, Σidf×14), no texto min(28, Σidf×6); palavra-chave no caminho da PASTA +10; extensão (xlsx → "Planilha / Cálculo" +30; imagem → "Prova / Print de conversa" +30); se ≥ 50% dos arquivos classificados da mesma pasta usam a peça, + round(20 × proporção).
- confiança = min(98, pontuação); descartar < 35; retornar top 3 com os "motivos" em texto ("nome contém “cobranca”", "pasta “Cobrança”", "70% dos arquivos da pasta são deste tipo").
- IDF calculado por escritório e cacheado (IMemoryCache, invalidar ao alterar peças/palavras).
- Nunca aplicar sozinha: só quando o usuário confirma (individual ou "aplicar ≥ 80%").
APRENDIZADO: ao classificar com uma peça DIFERENTE da sugestão principal, pegar a palavra mais característica (maior IDF, 4+ letras, não stopword) do nome do arquivo que ainda não é palavra-chave da peça e gravar em classificacoes_aprendizado (tenant). Retornar no response { aprendido: "palavra" } para o front mostrar.
LOGS: cada classificação/alteração/remoção gera log na estrutura de develop ("definiu a classificação de X: <peça>" / "removeu a classificação de X").
Performance: listagem e sem-classificacao paginadas; sugestões calculadas só para a página atual; nenhuma consulta N+1 (buscar peças/áreas uma vez por request).
