2. O QUE MUDA EM RELAÇÃO AO PROMPT ANTERIOR (aplique tudo)
========================================================================
2.1 Nome e forma: collection "classificacoes" → "classificacoesArquivos". Níveis "grupo/categoria/subcategoria" → "categoria/subcategoria/tipo". Renomeie modelos, DTOs, campos e textos de tela para essa nomenclatura (o que era "grupo" vira "categoria"; o que era "categoria" vira "subcategoria"; o que era "subcategoria/peça" vira "tipo"). paiId genérico → categoriaId e subcategoriaId explícitos.
2.2 Dono: tenantId → usuarioId (ID do USUÁRIO PAI, sempre; mesmo quando quem cria é o usuário adicional). Use o método existente (A3). Todas as consultas de classificação filtram por: padraoSistema = true OU usuarioId = <pai>.
2.3 O escritório SÓ CRIA TIPOS. Categorias e subcategorias são SÓ do sistema: remova do back e do front qualquer criação/edição/exclusão/ocultação de categoria e subcategoria pelo escritório (inclusive "Novo grupo", "Nova categoria", cadastro com filhos separados por ";", edição de cor).
2.4 Padrão do sistema é INTOCÁVEL: tipos/subcategorias/categorias padrão não podem ser editados, desativados nem excluídos. O back recusa (objeto de resultado com mensagem + 403/400 no padrão da API).
2.5 Tipos do escritório:
   - Criar: { subcategoriaId (de uma subcategoria padrão ativa), nome, palavrasChave? }. O back grava categoriaId (da subcategoria), usuarioId = pai, padraoSistema = false, ativo = true, nomeNormalizado, ordem = (maior ordem da subcategoria + 1), datas.
   - Editar: nome e palavrasChave (só tipos do próprio escritório).
   - NÃO EXCLUIR: sem DELETE. Em vez disso, DESATIVAR e REATIVAR.
   - Nome único: comparar pelo nomeNormalizado com os tipos VISÍVEIS da mesma subcategoria (padrão + do escritório). Validar antes de gravar e, se o índice único devolver DuplicateKey (gravação simultânea), devolver a mesma mensagem amigável: "Já existe um tipo com esse nome nesta subcategoria."
   - Normalização (um método único no back, ex.: NormalizarNome): minúsculo, remover acentos (NormalizationForm.FormD + remover NonSpacingMark), trocar espaços repetidos por um, Trim.
2.6 DESATIVAR TIPO COM ARQUIVOS:
   - GET classificacoes/tipos/{id}/uso → { totalArquivos }.
   - Front: se totalArquivos > 0, confirmar: "<N> arquivos usam este tipo. Ao desativar, eles ficarão sem classificação." [Cancelar] [Desvincular e desativar]. Se 0: confirmação simples.
   - Back (PUT classificacoes/tipos/{id}/desativar): 1) UpdateMany nos arquivos do pai com classificacao.tipoId = id → $unset classificacao; 2) ativo = false, atualizadoEm. Retorna quantos arquivos foram desvinculados. (Se o projeto já usa sessão/transação no Mongo, envolva os dois passos.)
   - PUT classificacoes/tipos/{id}/reativar → ativo = true (não reclassifica nada).
2.7 OCULTAR PADRÃO DO SISTEMA = SÓ VISUAL: remova ocultoPara e qualquer endpoint/campo/preferência de ocultar. No front, um botão com ícone de olho ("Ocultar padrão do sistema" / "Mostrar padrão do sistema") recolhe todos os itens padrão e mostra só os tipos do escritório (com a sua subcategoria/categoria como contexto). Estado só na tela (não grava; ao reabrir, volta mostrando tudo). Mesmo comportamento na central e no seletor.
2.8 FILTRO "MOSTRAR DESATIVADOS" na central: por padrão, só ativos; marcado, mostra também os tipos desativados do escritório (com selo "Desativado" e ação "Reativar"). Tipos desativados NUNCA aparecem no seletor nem nas sugestões.
2.9 APRENDIZADO SEM GRAVAR NADA: remova palavrasEscritorio e qualquer gravação de "palavra aprendida". O aprendizado passa a ser CALCULADO NA HORA:
   - Ao calcular sugestões, o back lê os arquivos JÁ CLASSIFICADOS do pai (só nome + classificacao.tipoId; amostra dos 2.000 mais recentes), conta as palavras dos nomes (normalizadas, 4+ letras, sem stopwords) por tipo e considera como "palavras aprendidas" do tipo as que aparecem em pelo menos 3 arquivos e em ≥ 30% dos arquivos daquele tipo.
   - Essas palavras somam ao lado das palavrasChave do catálogo no algoritmo de sugestão (mesmos pesos do prompt anterior), e o motivo mostra a origem: "nome contém “inadimplencia” (aprendido com 12 arquivos do escritório)".
   - Cache em memória por usuarioId (IMemoryCache, 10 minutos), invalidado quando o escritório classifica/desclassifica arquivos ou cria/edita/desativa tipos.
   - Remova o retorno { aprendido } e a mensagem "O sistema aprendeu…" do front.
2.10 LOGS: ficam para uma etapa posterior. Nesta etapa NÃO implemente log geral de classificações nem a aba "Histórico" da central (remova se já foi feita). Não grave "classificadoPor" no arquivo.
2.11 Sugestão inteligente (o resto continua como no prompt anterior): calculada no back por requisição, só sobre TIPOS visíveis e ativos; frase/palavras-chave/IDF/pasta/extensão/vizinhos; top 3 com confiança e motivos; nunca aplica sozinha; "Aplicar sugestões confiáveis (≥ 80%)" em lote. (A regra de extensão xlsx/imagem só vale se existir um tipo correspondente; se não existir, ignore.)
