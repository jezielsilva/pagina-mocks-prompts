LEVANTAMENTO DE FUNCIONALIDADES DE DOCUMENTOS (base para o permissionamento)
Objetivo: listar TODAS as funcionalidades do módulo Documentos (Nova Cloud) que existem HOJE no front e no back, para depois decidirmos qual permissão protege cada uma. NÃO alterar código, não criar branch de implementação. Só ler e entregar o relatório.

REGRAS DE PERMISSÃO QUE JÁ VALEM (para você classificar cada funcionalidade)
1. Usuário PAI (titular): acessa TUDO, sempre — os arquivos dele e de todos os adicionais. Nenhuma checagem o bloqueia.
2. Usuário ADICIONAL — 3 filtros, nesta ordem:
   a) ESCOPO (`visualizarTodosDocumentos`): true = vê todos os documentos do escritório, como o pai; false = vê só os que ele mesmo enviou/criou.
   b) CATEGORIA: para ver uma área, precisa da permissão de LEITURA do módulo dela. Sem ela, a área fica desabilitada na sidebar e TUDO dela some em Documentos (pastas, arquivos, contadores, gráfico de armazenamento, filtros, busca, favoritos, lixeira, fila de classificação).
      - Minhas pastas → Documentos (acesso ao módulo)
      - Tarefas → Tarefas › ExibirLista
      - Prazos → Prazos › ExibirLista + Documentos › Visualizar
      - Processos → Processos › ExibirLista
      - Pré-processos → Pré-processos › VisualizarDocumentos
      - Clientes → Clientes › Lista
      - Fornecedores e Financeiro → Financeiro › Lista
   c) AÇÃO: as ações sobre arquivos/pastas usam as chaves do módulo Documentos:
      - Visualizar (nível Visualização) → ler;
      - Remover (nível Remover) → hoje usada para TODAS as alterações;
      - Contratar (nível Contratação) → upgrade de armazenamento.
      IMPORTANTE: o sistema valida o nível pai usando UMA chave filha (ex.: "ExibirLista" representa a leitura). NÃO renomear nem reestruturar chaves; seguir o padrão existente.
