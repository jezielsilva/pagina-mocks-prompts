Instalar o vigia do Codex

O vigia olha o portal a cada 2 minutos. Quando aparece um prompt marcado para executar, ele abre uma janela do Codex já trabalhando nele. Quando o Codex termina, a entrega vira uma Issue no portal.

1Pré-requisitos

  • Codex CLI instalado e logado.
  • GitHub CLI (gh) instalado e logado. Sem admin: winget install --id GitHub.cli --scope user, depois gh auth login (GitHub.com → HTTPS → Login with a web browser).
  • Git instalado.

Depois de instalar qualquer programa, feche e abra o PowerShell de novo.

2Baixar o script

No portal, abra Vigia do Codex (PowerShell) e salve o arquivo vigia-codex.ps1 nesta pasta:

%USERPROFILE%\vigia-codex\

Ou deixe o PowerShell criar a pasta e baixar direto:

New-Item -ItemType Directory -Force "$env:USERPROFILE\vigia-codex" | Out-Null
Invoke-WebRequest https://raw.githubusercontent.com/jezielsilva/pagina-mocks-prompts/main/ferramentas/vigia-codex.ps1 -OutFile "$env:USERPROFILE\vigia-codex\vigia-codex.ps1"

3Abrir o PowerShell na pasta e liberar o script

Menu Iniciar → digite PowerShell → abrir (não precisa ser administrador). Não dê dois cliques no .ps1: a janela fecha sozinha.

cd "$env:USERPROFILE\vigia-codex"
Unblock-File .\vigia-codex.ps1
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

Se perguntar, responda S (ou Y).

4Conferir as ferramentas

codex --version
gh auth status
git --version

Os três precisam responder sem erro.

5Clonar o portal (se ainda não clonou)

Test-Path "$env:USERPROFILE\Documents\Portal Claude\pagina-mocks-prompts\itens.json"

Se responder False, clone:

git clone https://github.com/jezielsilva/pagina-mocks-prompts.git "$env:USERPROFILE\Documents\Portal Claude\pagina-mocks-prompts"

Os projetos precisam estar em %USERPROFILE%\elawadv (com web-proadv e api-proadv dentro).

6Testar uma vez, na mão

.\vigia-codex.ps1

Se houver prompt marcado para executar no portal, abre uma janela nova com o Codex trabalhando. Para levar a conversa ao app desktop, digite /app dentro dela.

Não abriu? Veja o log:

Get-Content "$env:USERPROFILE\vigia-codex\vigia.log"

7Instalar no Agendador (roda sozinho a cada 2 min)

.\vigia-codex.ps1 -Instalar

Roda enquanto você estiver logado no Windows. Para parar: .\vigia-codex.ps1 -Remover

8Como funciona no dia a dia

  • O Claude publica o prompt no portal com "executar": true.
  • Em até 2 min o vigia abre a janela do Codex. Você acompanha e responde se ele perguntar algo.
  • No fim, o Codex salva a entrega em %USERPROFILE%\vigia-codex\retornos\, e o vigia abre a Issue "Retorno Codex: …" no portal.
  • Você avisa o Claude no chat ("lê a issue"), e ele revisa e publica o próximo prompt.
  • Um prompt por vez: o próximo só abre quando o retorno do atual chegar.

?Problemas comuns

  • "… não é reconhecido": o programa não está instalado ou o PowerShell foi aberto antes da instalação. Instale e abra um PowerShell novo.
  • Pede administrador: use as opções --scope user ou peça para a TI. Não tente contornar o bloqueio.
  • Script bloqueado: repita o passo 3. Se a empresa bloquear o Set-ExecutionPolicy, avise o Claude.
  • Rodar de novo o mesmo prompt: o Claude republica com data nova. Ou apague a linha dele em %USERPROFILE%\vigia-codex\executados.txt.
  • Ficou travado em "aguardando retorno": o Codex não salvou o retorno. Salve a entrega manualmente em retornos\<id>.md ou apague em-andamento.txt.
